# 全链路无损预填、Engram 跨块预热与 DSpark 上下文检索（2026-11-18，v0.1.7）

基于 SGLang `main 084a5e9aae`（v0.1.6 环境），在不修改任何 SGLang 源码、保持 100% 数学无损的前提下，将底层共性预填/行表/弹性缓存优化下沉至 XTier 核心层，并在 `xtier/packs/deepseek_v4/` 加速包内补齐跨块 Engram 预热、DSpark 上下文草稿检索（Recall）与 SM120 小批量算子优化；同时完成 DeepSeek V4.1、GLM-5.3 Flash、Qwen3.8 Flash Next 三个模型的全套发布前回归、两轮 `agent_bench` 与各 15 分钟 `dsh` 真实任务验收。[回到文档目录](../README.md)

## 1. 改动拆解

### 1.1 XTier 通用核心层（全模型生效）

1. **1K–6K 长度绕过 `_split_prefill` 悬崖（`xtier/backend/method.py`）**：
   `_split_prefill` 以 `output_dtype=torch.float32` 调用预填计划，令 `_fp4_ready` 失效而回退慢路径。`XTIER_FP4_BYPASS_SPLIT=1`（默认开）在 `_fp4_ready(torch.bfloat16)` 成立时直接走 `_run_fp4`：4.2K 冷 prefill 从 `969.4` 升至 `1,693.5 tok/s`（`+74.7%`），`agent_bench` 多轮工具回传中位首字从 `2.27 s` 缩短至 `1.95 s`。
2. **`_run_fp4` 单次激活量化 + 融合 Gather/Scatter + 动态 `ws_cap`（`xtier/backend/prefill.py`）**：
   原来每个专家块切片都对子集做一次 `mxfp8_quantize` 和 `index_add_(part.float())`。`XTIER_PREFILL_FP4_FAST_GLUE=1`（默认开）改为每层对整批激活做一次 `mxfp8_quantize`，再用融合 Triton `_gather_fp8_and_ids` 与无原子 `_add_bf16_rows`（块内行唯一，确定性逐位一致）完成分发与 FP32 累加，40 层每块 48K 净省 `167 ms`。同时按当层实际最大切片行数 `ws_cap` 申请 CUTLASS 工作空间（小批量预填省约 `0.75 GiB` 瞬态显存）。
3. **NVMe 行表批内去重、LBA 升序大轮次读取与后台预热（`csrc/tables/rows.cpp`、`xtier/tables/__init__.py`）**：
   新增批内 `SeenTable` 行号去重，将单轮缺页聚合从 `2,048` 扩至 `16,384` 页并对 `(fd, 4KB 页)` 全局去重后按物理偏移升序并发 `pread`，同时导出只填缓存不拷出的 `xtier_rows_prefetch` 接口（DeepSeek Engram 与 Qwen3.8 PLE 行表通用）。
4. **弹性热专家槽跨模态预测保护（`xtier/cache/elastic.py`）**：
   `< max(hybrid_prefill_max, gpu_prefill_min)` 的小批量调用不分配 GPU 暂存槽和 CUTLASS 工作空间；`Governor.predict` 不再用这类样本去外推 `>= 1,024` 的 GPU prefill，彻底消除多轮会话跨过 1,024 token 边界时少估显存触发的紧急全量退槽。

### 1.2 DeepSeek V4 加速包（`xtier/packs/deepseek_v4/`）

1. **跨块 Engram 后台提前预热（`XTIER_ENGRAM_LOOKAHEAD=1`）**：
   长提示按 48K 分块时，第 14 层 Engram 查表完成后由守护线程用相同的 N-gram 哈希计算下一块的 Engram 行号并调用 `xtier_rows_prefetch` 预热进内存缓存，与第 15–39 层约 `4 s` 的 GPU 计算完全重叠，消除下一块第 1 层约 `396 ms` 的 NVMe 等待。合上通用项后每块 48K 净省 `563 ms`（388K 冷提示 `54.57 → 50.12 s`，`+8.9%`，贪婪 SHA-256 逐字一致）。
2. **DSpark 上下文草稿检索 Recall（`recall/`，`XTIER_RECALL=1`，启动台「上下文草稿检索」默认开）**：
   吸收并改造 `Yee-4.1` 的滚动哈希检索、非贪婪单热修正与置信度预算联动：修复 SGLang `084a5e9aae` 折叠草稿模式下漏更新 `proposal.verify_ids[:, 1:1+gamma]` 导致目标模型验证读到旧草稿的问题；为单卡（`TP=1`）增加未命中 **0 GPU kernel 发射** 快路径。候选词全部经主模型逐 token 验证，100% 无损。控制变量实测：多轮代码微调 `copy` 1/2/4 路 `185.9 / 240.1 / 284.8 → 205.8 / 268.0 / 381.5 tok/s`（贪婪输出 SHA-256 全一致），改写 `rewrite` 1/2 路 `+13.9% / +66.5%`，混合 4 并发 `191.2 → 332.3 tok/s`（`+73.8%`）。
3. **SM120 小批量内核覆盖与 Markov 头分发**：
   `wo_a` 分组投影行数上限 `16 → 64`（`ds_wo_a_check` 通过），`XTIER_MXFP8_B12X_ROWS` 默认 `1-24 → 1-32`（`ds_mxfp8_rows_check` 1–32 行逐位一致），DSpark 草稿 `markov_w2` 在单行 `M=1` 时补齐为 2 行触发 SM120 Tensor Core（`530 → 230 µs`，每步 `−0.30 ms`）。

### 1.3 实测证伪与排除项

- **Prefill `wo_a` 强转 W8A8 MXFP8**：权重本身是 W8A16，量化激活引入 `2.68%` 相对 L2 误差（有损）且因转置反慢 `2.8 ms/层`，不采用。
- **目标模型词表头 Cauchy-Schwarz 确定性剪枝（`Certified LM Head`）**：在真实 `head.weight [129280, 5120]` 上因 $\sqrt{5120}\approx 71.5$ 高维集中，仍有 `128,319 / 129,280`（`99.3%`）词无法被数学证伪，保持精确 BF16 词表头。
- **有损路由裁剪实验**：虽可减少冷专家读取，但长推理链在近同分处发生轨迹分支，按纯无损原则彻底移除不入库。
