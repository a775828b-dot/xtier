# 2026-10-26：冷专家池放到硬盘（DeepSeek V4.1 Flash 1017 模拟内存不够）

目标：内存放不下一个模型的全部路由专家时（DeepSeek V4.1 Pro 在 72 GB 显存 + 384 GB 内存上），每层只把一部分专家放内存，
其余放到 NVMe 上的冷专家池，用到时读回内存再算。池子大小和速度受限于硬盘速度和类型。用 DS4.1 Flash 1017（40 层 × 384 个
专家，每个 18.8 MB，共 289 GB）限制每层的内存槽来模拟，卸载 X = 10–50%。设计见 [design-cold-experts.md](../design-cold-experts.md)。

测法（RTX PRO 5000 + 2× EPYC 9334，NPS4 384 GiB；启动台的 DS 默认配置，只加 `XTIER_COLD_*`）：
- `tp-sim/cold_e2e.py`：温度 0、不思考的三道题——照抄一段 600 词的文字（778 token 提示、760 token 输出）、写代码（147 token）、
  算乘法；照抄逐字比对。
- `tp-sim/cold_ppl.py`：600 / 3000 / 12000 token 文档和 3000 token 源码的逐 token logprob（两轮，每轮前清前缀缓存）：NLL 和 prefill 时间。
- 生产的 agent_bench 64K 会话（约 20 步工具调用，首个请求 66K token 冷 prefill；长回复 = 输出够长的请求）。
- 读盘核对：冷存储全程 O_DIRECT；每次测量对 /proc/diskstats：读盘字节 = 请求字节，页缓存不增长（没有页缓存造成的假速度）。

## 结果：冷存储在 4 块盘上（傲腾 ×2、990 PRO、FX700，每块 72.2 GB）

|---|---|---|---|---|---|---|---|---|---|
| 不卸载 | 98.0 tok/s | 158.9 | 152.9 | 1.76 s | 4.3–5.3 / 6.3–8.2 s | 17.7 s | 1.14 s | 139.6 tok/s，30.5 ms / 步 | — |
| 10% | 85.8 | 93.9 | 147.4 | 2.33 s | 4.0–4.8 / 7.0–8.7 s | 18.0 s | 1.43 s | 141.9，32.8 ms | 2.5 |
| 20% | 77.8 | 95.0 | 130.2 | 2.29 s | 4.4–5.0 / 7.0–8.4 s | 18.1 s | 1.67 s | 118.7，37.8 ms | 8.8 |
| 30% | 79.1 | 79.3 | 119.2 | 2.34 s | 4.7–5.3 / 7.0–8.7 s | 19.6 s | 2.63 s | 101.3，43.9 ms | 16.8 |
| 40% | 49.8 | 57.4 | 101.4 | 2.94 s | 5.4–6.5 / 7.0–8.4 s | 19.0 s | 3.03 s | 56.0，89.9 ms | 32.4 |
| 50% | 41.5 | 50.3 | 100.3 | 3.89 s | 6.4–7.0 / 7.1–8.5 s | 20.1 s | 2.69 s | 56.1，73.8 ms | 48.0 |

- 精度：六次照抄全部 0 错；NLL 与不卸载的差在 −0.023 到 −0.004，都在不卸载自己两次启动之间的波动内（那里也差到 0.013）。
  冷模式下 GPU prefill 的专家分块顺序随内存驻留变化（BF16 分块输出的分组不同），所以同一配置两轮之间比不卸载的稍散。
- prefill：长 prompt 基本不受影响（跨层预读把读盘藏在计算和注意力后面，64K 冷 prefill 到 50% 也只多 2.4 s）。代价在中等长度的
  调用：一次几千 token 的调用会路由到这一层的大部分冷专家，每次都得读一遍（后续请求首字 1.14 → 1.4–3.0 s）。
- decode：每步缺失数随卸载比例超线性增长（2.5 → 48）；4 块盘上一次缺失约 0.7 ms（读盘等待，和计算重叠后）。
- 40%、50% 的 agent 只有 2–3 个长回复，每步时间散；看每步缺失数更可靠。

## 其他模型：GLM-5.3、Qwen3.8、MiniMax-M3.1（30%，10-26 晚 – 10-27）

同样 4 块盘、卸载 30%、启动台默认配置。每个模型：`cold_e2e.py`；`cold_ppl.py` 开 / 关冷专家各一次，逐 token 比 logprob；dsh 端到端
15 分钟（经 8000 网关的副本：一个会话读笔记把上下文填到约 20 万 token、每轮核对 ID 之和与门的颜色，再从上下文召回 3 个颜色，
剩下的时间做编码小任务）。

| 模型 | 冷存储（每块盘） | 每层在内存的专家 | 照抄 | dsh 15 分钟 | KV 填充 / 召回 | 服务日志错误 | 内存最低可用（关 → 开） |
|---|---|---|---|---|---|---|---|
| GLM-5.3 Flash NVFP4 | 42.8 GB（42 层） | 202 / 288 | 0 错 | 15 次运行 0 失败 | 3 / 3 轮、3 / 3 | 0 | 195 → 240 GiB |
| Qwen3.8 Flash Next | 6.4 GB（18 层在 CPU 引擎） | 358 / 512 | 0 错 | 65 次 0 失败 | 2 / 2、3 / 3 | 0 | 248 → 253 GiB |
| MiniMax-M3.1 Flash | 58.1 GB（57 层） | 90 / 128 | 0 错（写到输出上限前逐字一致） | 10 次 0 失败 | 4 / 4、3 / 3 | 0 | 142 → 204 GiB |
| DeepSeek V4.1 Flash 1017 | 72.2 GB（40 层） | 269 / 384 | 0 错 | 18 次 0 失败 | 4 / 4、3 / 3 | 0 | （开）145 GiB |

（GLM / Qwen / MiniMax 是下面的修复之后的结果；首次启动写冷存储约 0.3–1.2 s 一层，冷启动 GLM 402 s、Qwen 332 s、MiniMax 264 s。）

**修掉的问题：NVFP4 模型的短 prompt 用错全局缩放。** GLM 开冷专家后，600 token 的文档（低于 GPU prefill 门槛，走「热专家池 +
CPU」的混合 prefill）NLL 1.64 → 1.99 / 2.15，同一服务两轮单 token 最大差 27.7；长文本（GPU prefill）和 decode（照抄）正常。
MiniMax 的 dsh 有两处错（一轮少读 2 个文件、召回错 1 个颜色），不开冷专家的对照全对。原因：GPU prefill 在冷模式下把这一层的
全局缩放按本次调用的虚拟顺序（内存槽在前、冷暂存在后）重排，存在 `_cold_globals`，调用结束后 `_globals()` 一直返回这份；
热专家池（decode，首次使用时缓存）和混合 / 整层缓存的 prefill 按专家号取全局缩放，拿到的是别的专家的。MXFP4 的全局缩放都是 1，
所以 DeepSeek 看不出来。修法（`backend/prefill.py`）：`_globals()` 永远按专家号，本次调用的 prefill 内核用 `_call_globals()`；
不开冷专家时行为不变。`tests/cold_prefill_check.py` 每次调用后检查 `_globals()` 是按专家号的那份。修后 GLM 600 token
NLL 1.648 / 1.621（不开冷专家 1.639 / 1.646），与不开冷专家的逐 token 平均差 0.187，正好是不开冷专家自己两轮之间的 0.187。

**GPU prefill 两轮之间比不开冷专家时散（不是错）。** GLM / Qwen 的 3000–12000 token 文本，开冷专家后两轮逐 token 平均差
0.03–0.13 → 0.09–0.22，NLL 不变（有的更低）。这几个模型开着 `XTIER_PREFILL_ROUTE_ACCUM=1`：每个专家分块的路由结果立刻加进
token 的 FP32 累加器，加法顺序就是分块顺序，而冷模式下分块里是哪些专家随内存驻留变化。核对：GLM 开冷专家、
`XTIER_PREFILL_ROUTE_ACCUM=0`（按路由顺序求和）时两轮平均差 0.031 / 0.095 / 0.028，与不开冷专家的 0.033 / 0.096 / 0.027 相同。
MiniMax 的纯文本 NLL 本来就有 4–9，对极小的扰动很敏感（不开冷专家时 600 token 两轮就有 39% 的 token 差 > 1），PPL 判不了它，
看照抄和 dsh。

## 盘的要求：大块读带宽，不是 4K 随机读

冷专家池每次读一个 2.35 MB 的整片（一个专家在一个 NUMA 节点上的六段），一个专家 8 片，分到各盘。实际读法在四类盘上各测一次
（`tp-sim/disk_pattern.py`：100 GB 测试库，超过无 DRAM 盘 HMB 能覆盖的范围；同时读 k 片、随机位置）：

| 一次同时读 | 傲腾 P5800X | 三星 990 PRO（有 DRAM） | HP FX700（无 DRAM，PCIe 4.0） | HP EX900（无 DRAM，PCIe 3.0） |
|---|---|---|---|---|
| 8 片（一个专家整条在这块盘） | 6.55 GB/s，2.87 ms | 6.05，3.11 ms | 5.72，3.29 ms | 1.49，12.6 ms |
| 4 片（记录分到 2 块盘） | 6.14，1.53 ms | 5.77，1.63 ms | 5.26，1.79 ms | 1.49，6.33 ms |
| 2 片（分到 4 块盘） | 5.52，0.85 ms | 4.94，0.95 ms | 4.35，1.08 ms | 1.45，3.24 ms |
| 1 片 | 4.64，0.51 ms | 3.35，0.70 ms | 3.13，0.75 ms | 1.35，1.73 ms |
| 对照：4K 随机读 | 1509 MB/s | 613 MB/s | 252 MB/s | 190 MB/s |

- 不受 4K 随机读限制：无 DRAM 的 FX700 读大块只比傲腾慢约 14%（4K 随机读慢 6 倍）；EX900 慢在 PCIe 3.0 和主控（约 1.5 GB/s）。
- PCIe 4.0 的 NVMe 都能用，池子速度看大块读带宽和盘数；一次缺失要等最慢的盘，盘速差得多时用 `XTIER_COLD_PARTS` 给快盘多分片。
  无 DRAM 盘的数据放久后可能变慢（这块 FX700 旧数据顺序读曾测到 2.6–4.6 GB/s），傲腾 / 有 DRAM 的盘更稳。

## 开发中的取舍（X = 30%，同一套测法）

| 改动 | 照抄 decode | agent 长回复每步 | 说明 |
|---|---|---|---|
| 第一版：记录整条放一块盘、同步读、常驻核心 50% | 45.3 tok/s | — | 每步缺失 17 个，58% 的时间在读盘；12K prefill 9.2–10.7 s |
| 记录按节点分片到 2 块盘、常驻 30% | 59.5 | — | 一次缺失 2.6 → 1.58 ms |
| GPU prefill 异步读、按块等待 | — | — | 单层 x30：322 → 200 ms（全在内存 133 ms，读盘下限 177 ms） |
| 跨层预读（覆盖 ≥ 90% 才读）、split prefill、GPU 池专家不读 | 62.2 | — | 12K prefill 7.4–8.7 s；3000 token 回到 5.9–6.6 s |
| decode 层内重叠 | — | — | 单层回放：读盘等待 −21–24% |
| 不要常驻核心 + GPU 池专家初始计数 0（2 块盘） | 71.5 | 69.4 → 57.4 ms | 稳态每步缺失约 −15% |
| 冷存储分到 4 块盘 | 79.1 | 43.9 ms | 一次缺失（读盘等待）1.32 → 0.69 ms |

否决：
- 预门控预取：用第 L 层的 MoE 输入和下一层的门控提前猜（3001 token 实测输入：距离 1 的 top-6 猜中 59% 的冷专家路由），
  按 6 token 一步模拟，预读的只有 15–22% 被用上、读盘量 2.4–3 倍、只藏住约 37% 的缺失，x30 每步要读 1.07 GB，盘先饱和。
- 常驻核心：把 GPU 池的专家钉在内存，白占 CPU 要用的槽（见上表）；只去掉常驻、初始计数按排名时没有区别。
- 覆盖率不够也预读下一层：3000 token 的调用只用到约六成冷专家，全读反而慢 1.6 s。
