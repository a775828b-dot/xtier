## XTier 改了什么

XTier 挂在 SGLang 上的 69 处钩子里，有 21 处的目标这周改了，逐个对过新旧源码（这次又加了 1 处）：

| 改动 | 原因 |
|---|---|
| DeepSeek 索引器：SM12x 继续用 DeepGEMM（新钩子，挂在 `v41_indexer.is_sm100` 上） | 27bc1a0 把 DSv4.1 索引器的 DeepGEMM fp8_fp4 MQA-logits 路径从"SM100 及以上"收窄到"SM100 系列"，SM120 改走 torch / Triton 索引器：520K prefill 里每个 22K 分块随上下文从 5 s 涨到 12 s，总时间是原来的 1.8 倍（103 → 186 s）。同一个提交里别处的同类判断都保留了"SM100 及以上" |
| Engram：XTier 替换的 `EngramEmbedding.__init__` 补上 `mxfp4`、`row_bytes` 两个属性 | SGLang 开始支持 MXFP4 的 Engram 表，查表时会读这两个属性。XTier 放在 NVMe 上的行表只支持 FP8，遇到 MXFP4 的表直接报错 |
| 变长验证（compact）：删掉 [#13](https://github.com/a775828b-dot/xtier/pull/13) 的 Engram 哈希和 `token_req_indices` 两个钩子 | SGLang 自己按布局的 `qo_indptr` 把打包的 token 映射到请求（CUDA 图回放时会刷新）。`tests/engram_ragged_check.py` 改成直接检查 SGLang 的实现；校准预算那个钩子保留 |
| 其余 18 处不用改 | 都是包一层再调原函数；上游改的是参数、导入路径、注释和 NPU / ROCm 分支 |

另外：这周删掉的 40 多个环境变量 XTier 都没用到；`SGLANG_COMMIT`、`constraints.txt`、README 和[快速开始](../quickstart.md)的安装行、[支持情况](../support.md#v012-的测试环境)的环境表都更新了。

## 回归

测试机：RTX PRO 5000 72GB、2× EPYC 9334（NPS4）、384 GiB。三个模型都用启动台默认配置（开快速加载），对比的是 v0.1.0 的回归（SGLang 6162b07，[报告](2026-11-01-audit-fixes.md)）。

| 模型 | 照抄（单路 / 两路） | 序号回绕后照抄 | PPL NLL（v0.1.0 → 这次） | 64K prefill | 520K prefill | dsh 15 分钟 |
|---|---|---|---|---:|---:|---|
| DeepSeek V4.1 Flash 1017 | 0 错 / 0 错 | 2^31、2^32 都 0 错 | 1.2002 → 1.1986 | 4,894 → 4,840 tok/s | 4,593 → 4,617 tok/s | 37 个任务，0 失败 |
| GLM-5.3 Flash | 0 错 / 0 错 | 2^31 0 错 | 1.3855 → 1.3863 | 2,600 → 2,590 tok/s | 2,495 → 2,487 tok/s | 35 个任务，0 失败 |
| Qwen3.8 Flash Next | 0 错 / 0 错 | 2^31 0 错 | 1.2485 → 1.2465 | 5,237 → 5,236 tok/s | 4,794 → 4,806 tok/s | 65 个任务，0 失败 |

- DeepSeek 的数字是加了索引器钩子以后的。没加钩子时 64K prefill 4,333 tok/s、520K 2,641 tok/s，NLL 1.1996，照抄同样 0 错。
- DeepSeek 单路照抄有两次是结尾多抄一个 `</src>`（正文逐字一致），以前的版本就有。
- 64K 取第二次（第一次包括预热）。decode 每步和 v0.1.0 一样：DeepSeek 约 30 ms、GLM 约 28 ms、Qwen 约 14.5 ms。
- GLM 这次加载 460–750 s，比平时慢，是测试机上那块盘的老问题，和升级无关。
- dsh 15 分钟跑完的任务比升级前（同一天中午，SGLang 6162b07）少：DeepSeek 37 对 43、GLM 35 对 39、Qwen 65 对 72。是这次的任务平均多走了几步，速度没变：15 分钟里输出的 token 持平或更多；生成速度（输出 token ÷ 首字节之后的时间）DeepSeek 107.6 → 111.2、GLM 77.9 → 81.2、Qwen 174.6 → 177.3 tok/s；服务日志里单请求 decode 每步 30.7 → 30.2、30.5 → 29.7、14.7 → 14.6 ms。
