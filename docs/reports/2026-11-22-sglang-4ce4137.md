## 钩子审计与 XTier 改动

在 `4ce41378f9` 上逐个比对全部 31 个改过源码的被钩函数（原生 30 个、SM86 专属 1 个），清理了 3 组已被上游原生合入的过渡补丁，并补齐 1 处序列并行防御：

| 改动 | 原因 |
|---|---|
| `packs/deepseek_v4`：移除 `v41_indexer.is_sm100`、`_make_candidate_indexer` 与 `paged_indexer.py` | 上游（#49173）已拆分 `is_sm100_or_newer()`（SM120 原生走 DeepGEMM 稠密 prefill/decode），保持 `is_sm100()` 严格仅限 SM100 的 `SparseTableBackend`（且 `DenseBlocksBackend` 将 `use_deep_gemm_prefill` 拆为 `use_deep_gemm_publish` / `use_deep_gemm_consume`）；同时 `scoring.decode_scores` 已原生改为 `is_sm90 or is_sm120` |
| `packs/speculative`：移除 `EagleDraftWorker` 热词表拒绝采样绕过与手动 scatter | 上游已在 `EagleDraftWorker.alloc_memory_pool` 原生支持缩减热词表拒绝采样（`_init_draft_probs_vocab_scatter` + `draft_probs_vocab_size`），并新增融合草稿采样 `use_fused_draft_sample`；旧绕过会临时隐藏 `speculative_use_rejection_sampling=False` 导致关闭上游融合采样。清理后保留草稿温度缩放、低置信度截断验证与 `dspark_truncate`，GLM-5.3 每步 decode 反快约 1–1.5 ms |
| `packs/qwen4_exp/ple_blocks.py` 与 `tests/ple_blocks_check.py` | 上游 `Qwen4ExpPLELayer.forward` 新增 `layernorm_sp` 分支与 `_get_ple_forward_mode(forward_batch)`；`ple_blocks` 增加 `hidden_states.shape[0] < tokens` 回退保护，单测补充 mock `forward_batch` |
| `xtier/platform.py`（11-21 合入）：默认开启 CPU 多模态图像/视频解码与核数预算限流 | 上游 `BaseMultimodalProcessor` 重构为 `MultimodalProcessorMixin`，但仍默认 `gpu_image_decode=True` 与 `SGLANG_CPU_WORKERS=os.cpu_count()`；XTier 通用 serving 层默认强制 CPU 解码/预处理（Tokenizer/API 进程 0 显存占用）并将并发 worker 限制在非 MoE 预留核内（4 路并发高分 JPEG 实测 4.13 s 通过、0 OOM） |
| 其余 20 余处被钩函数 | 均为 NPU / AMD / ROCm / DP 分片 / beam search / 重构透传，对 XTier 包装无影响 |

`tools/check_sglang.py --strict` 原生 SM120（85 处钩子）、`--emulate sm86`（93 处）与 `--emulate sm100`（81 处）全通过，0 缺失、0 变动，新指纹已记入 [tools/hook_sources.json](../../tools/hook_sources.json)；15 项核心单元与 GPU 核测试（含 `cpu_image_check`、`ple_blocks_check`、`qsa_fp4_check`、`qsa_prefill_check`、`spec_truncate_check`、`engram_ragged_check`、`ds_mhc_post_check`、`ds_wo_a_check`、`ds_mxfp8_rows_check`、`hc_mix_check`、`fp8_weights_check`）全部通过。
