# 设计：冷专家池放到硬盘（`xtier/cache/cold.py`、`csrc/cold`）

内存放不下一个模型的全部路由专家时（例如 DeepSeek V4.1 Pro 在 72 GB 显存 + 384 GB 内存的机器上），每层只在内存里放一部分专家，
其余放在 NVMe 上的冷专家池里，用到时读进内存再算。池子大小和速度受限于硬盘的速度和类型：decode 每步要读它没命中的专家，
prefill 每次调用要把这一层用到的冷专家读一遍。`XTIER_COLD=1` 打开，默认关。实测见
[报告](reports/2026-10-26-cold-experts.md)。

开发用 DeepSeek V4.1 Flash 1017（40 层 × 384 个专家，每个专家 MXFP4 18.8 MB，全部 289 GB）限制内存模拟：每层只给
(1 − X) × 384 个内存槽。

## 结构

- **冷存储**（`csrc/cold/store.cpp`，编进 `libxtier_engine.so`）：每块盘一个文件，读写都用 O_DIRECT（不经页缓存：测到的就是盘，
  也不额外占内存）。一条记录 = 一个专家在 8 个 NUMA 节点上的分片，每片 2.35 MB（gate、up、两段 scale、down、scale 六段，
  就是引擎内存槽里的排法）；一条记录的 8 片分到各盘（`XTIER_COLD_PARTS` 可按盘速度给快盘多分，默认平均），读一个专家时
  所有盘同时出力。每块盘 8 个读线程；forward 等着的同步读排在 prefill 的异步读前面。清单（第一个目录的 `KEY.json`）记每层
  每块盘的起点和分法，重启时复用：每条记录核对首尾 4 KiB 的 CRC，不对或分法变了就整层重写。
- **内存槽**（`csrc/engine`，`xtier_create4`）：NUMA 分片只给 C = (1 − X) × 384 个槽，`slot_of` / `expert_of` 两张表。
  冷库存全部专家，任何专家都能换出，同一份存储可用于任意 X（常驻核心测过、没有采用，代码已移除，见「否决」）。
- **换入换出**：forward 开始前，把这次路由到但不在内存的专家读进“衰减使用次数最低”的槽（半衰期 50 次调用，
  `XTIER_COLD_HALF_LIFE`；不选这次调用要用的、正被 GPU 复制锁定的）。计数只记 CPU 的使用，所以 GPU 热专家池里的专家
  （decode 时由 GPU 算）会先离开内存，把槽让给 CPU 要算的专家；它们启动时的计数为 0（其余按排名给初值）。
  `XTIER_COLD_OVERLAP=1`（默认）：先发读、算已经在内存里的专家，读完再算缺的那几个，两段结果相加（不再与一次算完逐位一致，
  差在 FP32 末位）。
- **GPU 热专家池**：只从内存槽上传；换入时先锁定内存槽（`xtier_slot_pin`），复制落地后解锁；不在内存的专家这一轮不换入。
- **GPU prefill**（≥ 1024 token）：每次调用按当时的槽表建一个虚拟专家顺序——内存槽在前、冷专家在后，路由 id 在 GPU 上映射，
  全局 scale 和 FP4 驻留表跟着重排。冷专家读进锁页暂存区（排法与内存槽相同），上传时按块等待它的读取；GPU 池里有的专家
  不读，从池里复制（池变了就补读）。`XTIER_COLD_READ_AHEAD=1`（默认）：本层的调用路由到 ≥ 90% 的冷专家时
  （`XTIER_COLD_READ_AHEAD_COVER`），同时把下一层的冷专家读进另一块暂存区（两块轮流），盘在这一层计算和下一层注意力期间不停；
  只路由到一部分的中等长度调用不预读（会白读）。1024–6144 token 的 split prefill 照常：CPU 拿一段内存槽里的专家
  （不读盘、不换槽），GPU 算其余的。
- **CPU prefill**（混合 prefill 的 CPU 部分）：一次调用要的专家（不在内存的 + 在内存里可换出的）超过可换出槽的一半时分批。

## 盘的要求

读法是 2.35 MB 的整片（片内顺序）、片的位置随机，不是 4K 随机读。实测（报告里四类盘的表）：没有 DRAM 的 PCIe 4.0 盘读大块
只比傲腾慢约 14%，PCIe 3.0 的盘慢 4 倍；要的是大块读带宽，不是 4K IOPS。无 DRAM 盘的数据放久后可能变慢，傲腾和有 DRAM 的
盘更稳。
持续读也要测：HP FX700（无 DRAM）按这个读法满速读约 100 秒（约 460 GB）后塌到约 0.06 GB/s，温度正常、SMART 没有错误，
停下后约 7 分钟才恢复（10-27）；几秒钟的短测看不出来。一次缺失要等最慢的盘，一块会塌速的盘拖住整个池子。

池子大小由带宽决定：

- decode：每步缺失数 × 18.8 MB ÷ 带宽 = 每步多出的读盘时间（减去和计算重叠的部分）。缺失数随 X 超线性增长。
- prefill：每次 GPU prefill 调用要读 X × 289 GB × 路由到的冷专家比例；预读后，下限是每层冷专家字节 ÷ 带宽，低于每层计算
  加注意力的时间就完全藏住。

## 否决

- **预门控预取**（用第 L 层的 MoE 输入和第 L+1..L+4 层的门控提前猜专家）：3001 个 token 的实测输入上，距离 1 的 top-6 只猜中
  59% 的冷专家路由，按 6 token 一步模拟预取，预读的只有 15–22% 被用上，读盘量变成 2.4–3 倍，只藏住约 37% 的缺失；
  多出的读盘先把盘占满（x30 每步要读 1.07 GB）。
- **常驻核心**（排名前 30% 永不换出）：x30、两块傲腾时 agent 长回复每步 69.4 ms，对没有常驻核心（GPU 池的专家初始计数 0）的
  57.4 ms；它把 GPU 池的专家钉在内存里，白占了 CPU 要用的槽。只去掉常驻核心、初始计数仍按排名时没有区别（GPU 池的专家几百步
  内仍占着内存）。代码已移除。
