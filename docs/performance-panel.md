# 性能测试与监控

启动看板下方的测试面板针对当前在线服务运行，不应用尚未启动的参数，也不自动重启模型。左侧选择测试及参数，点击下方“开始测试”即可自动运行，无需复制命令；测试期间暂停其他客户端请求。服务级计数器可能包含其他流量，无法据此自动隔离单个请求。

## 测试选择

| 测试 | 用途 | 数据来源与约束 |
| --- | --- | --- |
| 固定输出 decode | 单请求生成基线 | 与 bench/decode_speed.py 一致的流式接口、温度 0、关闭思考、ignore_eos；固定输出上限，独立前缀 |
| 并发阶梯 | 单请求延迟与总吞吐折中 | 客户端实际同时提交 1、2、4、8、16 个请求；默认跳过超过服务上限的档位 |
| 上下文长度 | 长上下文性能退化 | 本地 tokenizer 构造约 1K、8K、32K、64K 提示；usage 给出实际长度；超出容量跳过 |
| 前缀缓存冷/热 | 缓存对首 token 延迟的影响 | 唯一前缀后重放同一提示，不清除全局缓存；检查 cached_tokens 而不是假定完全冷/热 |
| Agent 多轮 | 编码代理实际体验 | 复用 bench/agent_bench.py，64K 会话、最多指定交互步数；沙箱工具不会执行模型写出的代码 |
| 照抄正确性 | 性能变化后的输出质量核对 | 复用 bench/copy_test.py，两段源码，报告差异；不等于完整质量评估 |

需要测客户端 4/8/16 并发但服务上限较低时，显式开启排队压力模式。结果将标注含排队；它不能证明服务实际执行了相同大小的 batch。若要提高服务并发能力，另行调整启动配置、校准 SPS 并验证显存峰值，测试面板不代做这些操作。

Agent 测试自动适配当前 xtier/ 源码布局；旧上游 adapter/ 工作负载和此版本不是完全相同的任务，不直接混合基线。原有 decode/context/TTFT 脚本仍保留；统一面板修正了总吞吐的计时区间，并免去其本机不存在的默认语料路径。PPL、token flip 等需要额外评估语料或目标答案，本版不纳入一键性能测试。verify_step_bench 依赖外部 prompts 文件，验证步相关计数先使用已有服务 metrics 和 Agent 报告。

## 监控与测试就绪

GPU 功耗、显存、利用率和时钟在模型未启动、加载中或退出时仍持续采样。推理服务未在线时不请求其 metrics，吞吐、请求队列和 CPU 专家窗口保持缺失，曲线不填零。硬件采样成功不代表模型就绪；只有模型在线且没有启动或安装任务时才能开始测试。单项采样失败显示对应错误，不清除其他可用指标。模型重新启动后，服务计数器不会与上一次运行相减。

## 指标口径

- 总吞吐：成功输出 token 总数 / 整轮从发起请求至所有请求结束的墙钟时间，包含排队与首 token 等待；失败请求另计。
- 单请求 decode：服务 usage 的 (输出 token 数 − 1) / 首末内容块间隔。SSE 块可能含多个 token，因此是近似值，不是逐 token 内核计时。
- TTFT：发起请求至首个内容或 reasoning 内容块，包含排队、prefill、传输等；另存完整请求延迟。
- P50/P95：nearest-rank；小样本 P95 仅作参考。至少重复三轮，并保持上下文、输出长度、采样配置一致。
- CPU：日志最近窗口的每层调用耗时、专家命中率；没有时间戳的旧窗口可能早于本次测试，不能归因到本次请求。
- 调度阶段：SGLang scheduler_stage_seconds_total 的相邻采样增量；允许与 GPU 执行重叠，不与 CPU 窗口耗时相加。
- GPU：功耗、上限、显存、利用率、SM/显存时钟、温度；右侧六个监控卡片展示输出吞吐、功耗、利用率、显存、CPU 日志窗口耗时与排队请求，支持最近 1 分钟 / 5 分钟切换。曲线自打开页面开始积累，刷新后重新积累，缺失数据不填零。利用率不是 SM occupancy。
- 采样能量：有效 GPU 功耗采样区间的梯形积分，累计所有可见 GPU，包含空闲及其他任务。缺少两个有效样本时为空；不能当成完整请求能耗。
- 纯 GPU 内核耗时和 Engram 独立等待时间尚未采集，显示“未采集”。需要独立 profiler/引擎埋点才能精确归因，不用总时间减 CPU 时间来估算。

## 命令行与结果

```sh
python xtier/console/perf.py --kind decode --url http://127.0.0.1:18190 --model DeepSeek-V4.1-Flash-1017 --tokens 512 --rounds 3 --out bench/results/decode-baseline.json
python xtier/console/perf.py --kind concurrency --url http://127.0.0.1:18190 --model DeepSeek-V4.1-Flash-1017 --tokens 512 --rounds 3 --queue --out bench/results/concurrency-baseline.json
```

面板结果和配置快照保存在管理器状态目录的 benchmarks/ 中，保留完整文件，界面显示最近 20 次。开始测试时自动保存在线模型配置和本次测试选项。点击“查看测试结果”打开浮窗，上方是配置快照，下方是各轮测试结果、观测摘要和 JSON 导出。运行中也可查看已保存的配置；历史记录可随时重新打开。CLI 结果存到 --out。管理器一次只允许一个测试；测试运行中拒绝启动/安装操作。取消只终止测试客户端进程组，不停止模型；已提交请求可能仍在服务端收尾。重启管理服务会中断其测试进程，历史状态标记 interrupted。

建议先以固定输出和 Agent 测试建立基线，再只改变一个参数复测。主要指标是单请求速度、首 token 延迟、总吞吐、错误/照抄差异；功耗用作辅助观测，不以功耗上限作为验收目标。
